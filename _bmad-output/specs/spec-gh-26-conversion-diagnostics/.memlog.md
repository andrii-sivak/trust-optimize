- (direction) Owner 2026-11-20: collect conversion data from real sites to diagnose failures and to inform a later resource-management design. Do not implement adaptive pace, the resource gate, or a new memory estimate.
- (direction) Owner: JSONL files, no detailed events in the database. One explicit enable switch, default off. No new admin button or screen.
- (direction) Owner: while the switch is off, no extra diagnostic measurements and no diagnostic file writes. A diagnostics error does not interrupt conversion and does not change its decision.
- (direction) Owner: log the start of a variant conversion and its result. The start line is durable before the heavy call so a dead process leaves evidence. Do not log each internal call or each queue poll.
- (direction) Owner: want time, site, job, attachment, attempt, size name, format, source dimensions and bytes, editor, requested quality and the value the editor reports, duration with load and encode split when possible, available memory and CPU figures that say what they measure, result, skip or error reason, output bytes.
- (direction) Owner: PHP, editor and library versions, SAPI and known limits are a separate event, not repeated in full on every variant.
- (direction) Owner: do not present missing data as known. PHP memory is not native-encoder memory. System load is not this process. A missing final line does not prove OOM. Mark unavailable figures explicitly. No separate-process polling and no external service.
- (direction) Owner: per site, not reachable by a public URL, rotation, one size cap, keep at most 60 days. Cleanup must not depend only on Action Scheduler. Do not write URLs, file names, image bytes, secrets, or user data without need.
- (direction) Owner asked for a minimal useful v1: what is reliable and cheap versus what to defer. Do not add a metric only because it can be collected. Spec must cover measurement points, event format with examples, the switch, storage and cleanup, and checks for off mode, write failure, parallel writes, and size limits, plus a practical overhead measurement on the stand. No implementation until the spec is agreed. No push, merge, or GitHub change.
- (constraint) AD-18 binds this spec. Amended 2026-11-20 on this branch: retention is 60 days; cleanup has a non-AS path; diagnostic-only work does not run while the switch is off; AD-11 does not depend on the switch; a recording failure does not interrupt or redirect a conversion; a field names its scope; a missing result line is not a cause; pace and gate lines are not invented before those features exist. File location stays the spec's decision inside AD-18 privacy.
- (note) Code today: ImageConverter::convert opens the editor at get_editor_for_target_mime before save_with_quality. Both can kill the process. No diagnostic writer exists. ImageLimits::skip_reason uses width*height*5 against 60 percent of memory_limit minus memory_get_usage and is not changed. Attachment attempts are an integer; attempt_token is bin2hex(random_bytes(16)) and is a capability secret. Variant rows already carry size_name, format, width, height, source_file_size. job_id is on the attachment row and is null outside a bulk. Settings are one option array trust_optimize_options; unknown keys are dropped on sanitize. Uninstall deletes trust_optimize_* options only after remove_data_on_uninstall finishes generated-file cleanup. wp_upload_dir basedir is per site. The stand's tools README shows /sys/fs/cgroup/memory.max is readable in the tool containers.
- (decision) v1 records four events only: environment, variant_start, variant_result, attachment_skip. No pace, gate, queue-poll, or per-editor-call events.
- (decision) The enable switch is the checkbox diagnostics inside trust_optimize_options, default 0, on the existing Limits section. No new screen, no clear-logs button, no WP-CLI command, no REST field, no hook.
- (decision) variant_start is flushed after the source file is known to exist and before get_editor_for_target_mime. Editor class, reported quality, durations, and output bytes belong to variant_result because they do not exist yet at start. A failure before the editor, including missing_file, is a result with no start, so a start line always means the heavy call was about to run.
- (decision) attachment_skip is one line per attachment when planning skips without opening an editor (too_large, insufficient_memory, unknown_dimensions, and the other existing planner reasons). It is not a start, so it cannot be read as a dead encode.
- (decision) Attempt identity in the log is the integer attempts count plus attempt_source queue or sync. The attempt token is never written.
- (decision) Environment is written at the first logged line of a job and again when its fingerprint changes, including SAPI. Variant lines carry only a short env hash. Conversions with a null job_id write it once per process and again when the fingerprint changes.
- (decision) CPU is getrusage(RUSAGE_SELF) user and system time, split around editor load and encode, labeled process CPU. Wall time is hrtime around those two calls, labeled process wall clock. Both are on the result only.
- (decision) Memory on start and result is memory_get_usage(true) and memory_get_peak_usage(true), labeled PHP allocator pages. Peak is since process start. It is not encoder RSS.
- (decision) Cgroup memory.current and oom_kill are read at start and result when the process cgroup files are readable, labeled as the cgroup including neighbours. Otherwise the keys are cgroup=unavailable and cgroup_reason. PHP memory is never copied into a cgroup field. Unavailability is cached for the process.
- (decision) Deferred as not worth v1: sys_getloadavg, PSI, cpu.stat throttle delta, frontend latency, fsync, output hashes, Action Scheduler action id, per-variant environment, a separate watcher process, and writing the in-flight step onto a variant or attachment row.
- (decision) Environment limits, once: PHP version, SAPI, WordPress version, memory_limit bytes, max_execution_time, GD version and WebP/AVIF flags, Imagick extension version, ImageMagick version with URLs removed, editor class names, cgroup memory.max, swap max, and cpu.max raw text. Imagick memory and thread limits only if readable without decoding an image, else unavailable. Numeric conversion settings (qualities and the two format switches) ride this event.
- (decision) Storage path is wp_upload_dir basedir / trust-optimize-logs / {32-hex token}. Token is option trust_optimize_log_token, autoload false, created on first use while enabled, not inside trust_optimize_options because sanitize drops unknown keys. The plugin never builds or prints a URL. It writes .htaccess deny, web.config deny, and index.php. Admins with manage_options see the filesystem path in the existing field description.
- (assumption) Per-site cap is 64 MiB, active file rotates at 8 MiB, one JSONL line is at most 1024 bytes. These numbers are a proposal, not an owner figure. 60 days is the owner figure. A quiet site is aged out by time; a Halilit-scale run keeps roughly the last hour because 28 attachments/min times 17 sizes times 2 formats is about 45 MB/hour at 400 bytes times two lines.
- (decision) Before a start line, prune then refuse the start when remaining room is under two max lines, so a start is not written when its result cannot fit. A result for a start already written may exceed the cap by one line. Further starts wait until prune frees an older archive.
- (decision) Writers flock a dedicated write.lock, append one JSON line, fflush, and unlock. No fsync. A short write or encode failure is swallowed and the conversion continues. Rotation renames the active file under the same lock.
- (decision) Prune runs from a write, at most once an hour, and from admin_init for manage_options, at most once an hour, using option trust_optimize_log_pruned_at. It does not schedule Action Scheduler. Idle sites with no admin visit and no logged write can keep files past 60 days until the next such request. Deactivation does not delete logs.
- (decision) Uninstall with remove_data_on_uninstall deletes the diagnostics directory before trust_optimize_* options are dropped. If the directory remains, trust_optimize_log_token is kept and the existing uninstall error_log names the directory. Without the flag, logs and the token stay, same as other plugin data.
- (decision) Error text is not stored raw. The log keeps the machine reason code. A message is stored only after URLs and path-like tokens are removed, capped at 200 characters; if nothing remains, the message is null.
- (decision) No schema change, no new public hook, no REST or WP-CLI change. The implementation commit updates readme Settings and the privacy notice, and adds one Unreleased changelog bullet. Comments do not cite issues or this spec.
- (capability) CAP-1 An administrator can turn conversion diagnostics on or off, default off, and off means no diagnostic-only work. Success: a default conversion creates no diagnostics directory and a test subclass counts zero cgroup and cpu samples; the variant outcome matches a run that does not construct the logger.
- (capability) CAP-2 While on, a variant conversion leaves a start line flushed before the editor opens and a result line afterwards. Success: a test editor load sees the start line already in the file; a finished conversion's result status and reason match the variant row; stopping inside the editor leaves the start line and no result line.
- (capability) CAP-3 Environment is its own event at job start and when the fingerprint changes, and variant lines do not repeat it. Success: three variants of one unchanged job produce one environment line; changing avif_quality writes a new environment line before the next variant; variant lines carry only the env hash.
- (capability) CAP-4 A diagnostics failure does not interrupt conversion or change its outcome. Success: a non-writable diagnostics directory yields the same variant status, reason, and output bytes as the same conversion with diagnostics off.
- (capability) CAP-5 Each site's diagnostics stay in that site's directory, inside the cap and 60 days, and are removed without Action Scheduler. Success: site B does not write into site A's directory; prune deletes a file older than 60 days and schedules no Action Scheduler action; uninstall with the remove-data flag deletes the directory; admin HTML, REST, and WP-CLI contain no log URL.
- (capability) CAP-6 Figures name what they measure, and missing figures are explicit. Success: an unreadable cgroup yields cgroup=unavailable and does not copy PHP memory into a cgroup field; the memory scope string says PHP allocator; no row's reason becomes an OOM conclusion because a result line is absent.
- (question) Does the owner accept the residual risk that a web server which ignores .htaccess can still serve the JSONL if the unguessable uploads URL is known, or must the plugin refuse to write until a directory outside the document root is configured?
- (assumption) The filesystem path is shown to manage_options on the existing settings screen so the operator can find the files without a new command. The path is not a URL.
- (assumption) Imagick resource limits are read once per environment event only when that read does not decode an image. A failure marks imagick_limits unavailable.
- (note) Overhead check is manual on tools-php80, not a CI gate: 1000 start-plus-result pairs with no encode, report median and p95; soft target median under 5 ms. Plus three WebP converts of the existing test JPEG with the switch off and on. Also confirm memory.current is an integer on that stand when the cgroup file is readable.
- (decision) Supersedes the environment cadence: one environment line per process per (job_id, fingerprint), remembered in the process, not deduplicated by reading the log. Another worker of the same job may write the same block. Null job_id is once per process until the fingerprint changes. Both that line and the start line are flushed before the editor opens.
- (decision) The attempt-source field is attempt_source, not source, so it is not read as a file path. attachment_skip source_bytes is null unless wp_filesize already ran; dimensions are the ones the limit check already computed.
